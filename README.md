# RGR-BDZU
Консольний застосунок на Python 3 (Psycopg 3) з архітектурою MVC для керування медичною базою даних PostgreSQL. Реалізовано CRUD-операції, пакетну генерацію тестових даних засобами SQL та параметризований пошук. (РГР з дисципліни «Бази даних та засоби управління»).
# Розрахунково-графічна робота: Застосунок бази даних PostgreSQL («Медична інформаційна система»)

Консольний прикладний застосунок мовою **Python 3** для взаємодії з реляційною базою даних **PostgreSQL** з використанням бібліотеки **Psycopg 3** (без використання ORM) та архітектурного шаблону **Model-View-Controller (MVC)**.

Виконано в межах дисципліни **«Бази даних та засоби управління»**.

---

## Мета роботи

Набуття практичних навичок розроблення прикладного застосунку, що взаємодіє з реляційною базою даних PostgreSQL засобами параметризованих SQL-запитів, підтримує CRUD-операції з контролем цілісності даних, виконує пакетну генерацію великих обсягів псевдовипадкових тестових даних засобами СУБД, здійснює складний пошук із вимірюванням часу виконання та має чітку структуру коду за шаблоном MVC.

---

## Опис предметної області та структури бази даних

База даних моделює роботу медичного закладу (поліклініки/лікарні) і забезпечує облік лікарів, пацієнтів, довідника хвороб, компетенцій лікарів щодо лікування захворювань, записів на прийом та встановлених діагнозів.

### Схема таблиць БД (з Лабораторної роботи №1):

1. **`Лікар`** — довідник лікарів медичного закладу:
   * `Ліцензія` (`VARCHAR`, **PRIMARY KEY**) — унікальний номер медичної ліцензії лікаря;
   * `ПІБ` (`VARCHAR`) — прізвище та ініціали лікаря;
   * `Спеціалізація` (`VARCHAR`) — фахова спеціалізація (Терапевт, Хірург, Кардіолог тощо).
2. **`Пацієнт`** — реєстр пацієнтів:
   * `Номер мед. картки` (`VARCHAR`, **PRIMARY KEY**) — унікальний номер медичної картки пацієнта;
   * `ПІБ` (`VARCHAR`) — прізвище та ініціали пацієнта.
3. **`Хвороба`** — класифікатор захворювань:
   * `Код` (`VARCHAR`, **PRIMARY KEY**) — унікальний код хвороби;
   * `Назва` (`VARCHAR`) — назва діагнозу/захворювання.
4. **`Лікування`** — таблиця зв'язку компетенцій (які хвороби лікує конкретний спеціаліст):
   * `Ліцензія_лікаря` (`VARCHAR`, **FOREIGN KEY** $\rightarrow$ `Лікар.Ліцензія`);
   * `Код_хвороби` (`VARCHAR`, **FOREIGN KEY** $\rightarrow$ `Хвороба.Код`);
   * **Складений PRIMARY KEY:** `(Ліцензія_лікаря, Код_хвороби)`.
5. **`Запис`** — журнал записів пацієнтів на прийом до лікарів:
   * `Ліцензія_лікаря` (`VARCHAR`, **FOREIGN KEY** $\rightarrow$ `Лікар.Ліцензія`);
   * `Номер_пацієнта` (`VARCHAR`, **FOREIGN KEY** $\rightarrow$ `Пацієнт."Номер мед. картки"`);
   * `Дата_запису` (`TIMESTAMP WITHOUT TIME ZONE`) — дата і час візиту;
   * **Складений PRIMARY KEY:** `(Ліцензія_лікаря, Номер_пацієнта, Дата_запису)`.
6. **`Діагноз`** — історія встановлених пацієнтам діагнозів:
   * `Номер_пацієнта` (`VARCHAR`, **FOREIGN KEY** $\rightarrow$ `Пацієнт."Номер мед. картки"`);
   * `Код_хвороби` (`VARCHAR`, **FOREIGN KEY** $\rightarrow$ `Хвороба.Код`);
   * `Дата_Захворювання` (`TIMESTAMP WITHOUT TIME ZONE`) — дата фіксації захворювання;
   * **Складений PRIMARY KEY:** `(Номер_пацієнта, Код_хвороби, Дата_Захворювання)`.

## Структура проєкту та архітектура MVC

Програмний код організовано за шаблоном **Model-View-Controller (MVC)** з чітким розділенням відповідальностей:

```text
├── large_queries/                     # Зовнішні параметризовані SQL-скрипти
│   ├── generate_doctor.sql            # Генерація записів для таблиці "Лікар"
│   ├── generate_patient.sql           # Генерація записів для таблиці "Пацієнт"
│   ├── generate_illness.sql           # Генерація записів для таблиці "Хвороба"
│   ├── generate_doctor-illness.sql    # Генерація зв'язків для таблиці "Лікування"
│   ├── generate_doctor-patient.sql    # Генерація записів на прийом ("Запис")
│   ├── generate_patient-illness.sql   # Генерація історії хвороб ("Діагноз")
│   ├── search_1.sql                   # Пошуковий запит №1 (Записи на прийом)
│   ├── search_2.sql                   # Пошуковий запит №2 (Історія діагнозів)
│   └── search_3.sql                   # Пошуковий запит №3 (Статистика лікарів з GROUP BY / HAVING)
├── main.py                            # Точка входу в застосунок
├── Controller.py                      # Компонент Controller (керування потоком виконання)
├── Model.py                           # Компонент Model (взаємодія з PostgreSQL через Psycopg 3)
├── View.py                            # Компонент View (консольний інтерфейс користувача)
├── .env.example                       # Шаблон файлу конфігурації підключення до БД
├── requirements.txt                   # Перелік залежностей проєкту
└── README.md                          # Документація проєкту
```

### Розподіл відповідальностей між компонентами:
* **`Model` (`Model.py`)**: Інкапсулює всю роботу з СУБД PostgreSQL за допомогою драйвера `psycopg`. Відповідає за безпечну побудову динамічних ідентифікаторів (`psycopg.sql.Identifier`), виконання параметризованих CRUD-запитів (`fetch_all`, `insert_row`, `remove_row`, `edit_row`), пакетну генерацію даних (`generate_data`) та виконання пошукових запитів із хронометражем часу виконання (`execute_search`). Перехоплює низькорівневі винятки PostgreSQL (`ForeignKeyViolation`, `UniqueViolation`, `InvalidDatetimeFormat`, `UndefinedTable`) та транслює їх у зрозумілі повідомлення без виведення сирого системного стека. Не містить жодних викликів консольного вводу/виводу.
* **`View` (`View.py`)**: Відповідає виключно за взаємодію з користувачем через термінал. Форматує та відмальовує ASCII-таблиці з автоматичним розрахунком ширини стовпців (`draw_table`), відображає головне та пошукове меню (`show_menu`, `show_search_menu`), зчитує вхідні дані (`recv_row`, `recv_input`) і виводить інформаційні повідомлення та помилки. Не має прямого доступу до бази даних.
* **`Controller` (`Controller.py`)**: Виступає посередником між `View` та `Model`. Містить головний цикл програми (`run()`), обробляє команди меню (`Choice`), запитує метадані схеми з `Model`, передає їх у `View` для відображення підказок (`*` для первинних ключів, `-` для звичайних атрибутів) і централізовано перехоплює помилки бази даних.

## Залежності та вимоги до середовища

* **СУБД:** PostgreSQL 14+ (адміністрування через pgAdmin 4)
* **Мова програмування:** Python 3.10+
* **Бібліотеки Python:**
  * `psycopg[binary] >= 3.1` — сучасний адаптер PostgreSQL для Python (DB-API 2.0).

## Налаштування

**Налаштуйте підключення до PostgreSQL:**
   * Переконайтеся, що сервер PostgreSQL запущено, а таблиці з Лабораторної роботи №1 створені у цільовій базі даних.
   * Скопіюйте файл `.env.example` у файл `.env` та вкажіть ваші реальні параметри підключення:
     ```text
     dbname:postgres
     user:postgres
     password:your_password
     port:5432
     ```
   * *(Також параметри підключення можна ввести вручну безпосередньо під час старту програми в консолі).*

**Запустіть застосунок:**
   ```bash
   python main.py
   ```
   При появі запиту `To skip login type SKIP:` введіть `SKIP` для автоматичного завантаження налаштувань із файлу `.env`, або натисніть `Enter` для ручного введення параметрів.

## Опис меню користувача та основних команд

Після запуску в консолі відображається головне меню застосунку:

* **`1` — Show table (Перегляд таблиці):** Виводить вміст обраної таблиці у вигляді відформатованої таблиці. Можна вказати конкретні стовпці через кому або натиснути `Enter` для виведення всіх стовпців.
* **`2` — Insert a row into the table (Додавання запису):** Виводить шаблон атрибутів обраної таблиці та послідовно зчитує значення полів для вставки нового запису (`INSERT ... RETURNING *`).
* **`3` — Remove a row from the table (Видалення запису):** Підсвічує ключові поля таблиці символом `*`, зчитує значення первинного (зокрема складеного) ключа та видаляє відповідний запис із контролем зовнішніх ключів (`DELETE ... RETURNING *`).
* **`4` — Edit a row in the table (Редагування запису):** Дозволяє обрати існуючий запис за його первинним ключем (`*`) та ввести нові значення для оновлення атрибутів (`UPDATE ... RETURNING *`).
* **`5` — Generate a set amount of data (Пакетна генерація даних):** Генерує задану користувачем кількість псевдовипадкових записів (зокрема 100 000+ рядків) безпосередньо засобами SQL (`generate_series`, `random()`, `array_agg`) із дотриманням обмежень `UNIQUE` та `FOREIGN KEY`.
  > **Рекомендований порядок генерації:** спочатку згенеруйте дані для батьківських таблиць (`Лікар`, `Пацієнт`, `Хвороба`), а потім — для залежних сполучувальних таблиць (`Лікування`, `Запис`, `Діагноз`).
* **`6` — Search (Параметризований пошук у декількох таблицях):** Відкриває підменю з 3 комплексними пошуковими запитами та виводить час виконання кожного запиту в мілісекундах (`ms`):
  1. Пошук записів на прийом (`Запис` + `Лікар` + `Пацієнт`) за шаблоном спеціалізації лікаря (`LIKE`), ПІБ пацієнта (`LIKE`) та діапазоном дат (`BETWEEN`).
  2. Пошук історії діагнозів та рекомендованих лікарів (`Діагноз` + `Пацієнт` + `Хвороба` + `Лікування`) за шаблоном назви хвороби (`LIKE`) та періодом захворювання (`BETWEEN`).
  3. Агрегована статистика завантаженості лікарів (`Лікар` + `Запис` із використанням `GROUP BY` та `HAVING`) за шаблоном ПІБ лікаря (`LIKE`), періодом прийому (`BETWEEN`) та діапазоном кількості візитів (`COUNT(...) BETWEEN min AND max`).
* **`7` — Exit (Вихід):** Коректне завершення роботи програми.
